Abstract
This report presents the work carried out during a six-month internship at FIT - FIRST Information Technology, Muscat, Oman on customer feedback automation, where this platform represents the second delivered client project. The objective was to design, implement, and deploy InsightPulse, a multi-channel survey platform. A unified relational schema was developed to consolidate customer submissions across Web forms, WhatsApp (Meta Cloud API), and automated outbound Voice AI calls (VAPI). The backend is constructed in Node.js/Express with a fallback LLM analysis pipeline (DeepSeek-Chat/Gemini-2.0-Flash on OpenRouter) that normalizes raw feedback comments into structured Plutchik emotion ratings and categorizes themes. A React 18 dashboard polls the PostgreSQL Neon database every 30 seconds using TanStack Query. Operational trials indicate that web responses are ingested under 3 seconds, WhatsApp questions dispatch within 1.5 seconds, and VAPI webhooks process within 1 second, validating that structured LLM parsing can successfully replace manual customer experience review.
Index Terms: Customer Experience, Voice AI, WhatsApp Business API, Sentiment Analysis, Plutchik Emotions, Large Language Models.

1. Introduction

Modern businesses rely heavily on customer feedback metrics, such as Customer Satisfaction (CSAT), Net Promoter Score (NPS), and Customer Effort Score (CES), to evaluate operational performance. However, traditional systems are plagued by fragmented collection channels, slow manual reviews, and an inability to process voice and chat messages efficiently. Customer experience data is frequently siloed, leaving organizations without a single source of truth.

This report describes InsightPulse, a unified, AI-powered customer feedback platform built as the second client project during my six-month Internship-II (DA 378) at FIT - FIRST Information Technology, Muscat, Oman. InsightPulse automates feedback collection across Web, WhatsApp, and outbound phone lines, translating raw customer conversations into structured, operational database records. The remainder of this report describes the problem formulation, system workflow, implementation parameters, and validation metrics.

2. PROBLEM STATEMENT AND OBJECTIVES

2.1. Problem Statement

Gathering customer sentiment across multiple channels creates data silos. Voice transcripts and chat messages are complex and subjective, making them difficult to quantify at scale. Furthermore, manual sentiment classification suffers from high latency and human bias, which prevents organizations from quickly resolving issues. The challenge is to construct a system that can ingest voice, chat, and web submissions, store them in a unified relational schema, and automatically extract structured sentiment metrics and recommended action items in real-time.

2.2. Objectives

The specific goals of this project are:

  1. To design and implement a unified relational database schema that connects submissions across Web forms, WhatsApp chat sessions, and Voice calls.
  2. To build a state-machine-driven Meta WhatsApp engine to sequentially deliver localized questions and check customer inputs.
  3. To integrate an outbound Voice AI dialer (VAPI) that conducts telephone surveys and passes structured ratings directly back to the database.
  4. To establish a resilient LLM analysis pipeline via OpenRouter that maps comments to Plutchik's 8 basic emotions and generates operational recommendations.

3. METHODOLOGY / APPROACH

3.1. Overall Workflow

The InsightPulse data pipeline operates through five sequential stages: (1) Campaign Trigger: Admins dispatch surveys from the React interface or pull contacts from Zoho CRM via OAuth. (2) Channel Execution: Surveys are active on Web pages, sent as interactive WhatsApp messages, or run via an automated outbound VAPI phone call. (3) Ingestion & Parsing: Web and WhatsApp text comments are sent to the backend API; VAPI directly parses ratings via a webhook. (4) Asynchronous LLM Analysis: The LLM analyzes customer comments, categorizes themes, scores emotions, and saves the outputs to PostgreSQL. (5) Dynamic Dashboard Updates: The React client pulls these metrics to update visual analytics in real-time.

3.2. Technical Details

The backend is built in Node.js, Express, and TypeScript, utilizing Drizzle ORM to connect to a Neon serverless PostgreSQL database. The AI analysis engine is defined in the backend services. The server compiles customer comments and sends them to OpenRouter with a structured JSON prompt:

Prompt constraint: Set system role to survey analyst; enforce JSON mode with response_format = {"type": "json_object"}; set temperature to 0.3 to ensure consistent scoring.

To prevent downtime, the server implements a model failover chain:
Primary: DeepSeek-Chat → Fallback: Gemini-2.0-Flash
If the primary model times out or returns malformed text, the catch block transparently retries the analysis using the secondary model. A regular expression matches the JSON block in the output, which is then validated using a Zod schema.

3.3. LLM Orchestration Scope

The Large Language Model (LLM) is utilized across six distinct operational domains in the platform backend to automate text evaluation and content generation:

  • Survey Response Analysis: Analyzes incoming feedback text to classify positive/neutral/negative sentiment, score 8 Plutchik emotions, estimate CSAT/NPS/CES/EVI, extract themes, and recommend actions.
  • Dynamic Survey Generation: Creates complete survey question arrays from an admin's title and criteria prompt.
  • Real-Time Risk Detection: Asynchronously scans feedback using streaming LLM queries to identify high-priority operational risks or compliance threats.
  • Executive Leadership Insights: Periodically aggregates and digests historic customer feedback data to generate high-level trends for company leadership.
  • Employee Retention Analysis: Evaluates exit interview surveys to flag employee retention issues and construct mitigation recommendations.
  • Task-Oriented Action Plans: Automatically generates operational checklists for customer support teams when critical feedback is received.

4. EXPERIMENTS AND RESULTS

4.1. Experimental Setup

The system was evaluated inside a sandbox environment using mock survey campaigns. Outbound voice calls were tested using VAPI endpoints with local test phone numbers. WhatsApp messaging was verified using the Meta Graph API v21.0 in developer mode. The local development environment was set up on a macOS platform running Node v22.19, Vite, and a serverless Neon database instance. Integration tests verified that survey responses correctly triggered LLM API calls and successfully updated the database tables.

4.2. Results

Testing showed that the system processed survey entries quickly and reliably. Under sandbox conditions, web submissions (including LLM analysis) took less than 3 seconds to update the dashboard. WhatsApp responses proceeded to the next question within 1.5 seconds, and VAPI webhook calls processed in under 1 second. The TanStack Query client correctly updated the dashboard tabs every 30 seconds, demonstrating that the unified database schema can handle multi-channel inputs without data loss or pipeline blockages.

5. DISCUSSION

A key trade-off in the system design was choosing between LLM accuracy, latency, and cost. While DeepSeek-Chat provides deep sentiment analysis, it occasionally suffers from API latency. Using Gemini-2.0-Flash as a fallback resolved this, keeping the average analysis time under 3 seconds. Additionally, VAPI’s direct structured output webhook bypassed the LLM pipeline entirely, reducing costs and latency for voice interactions. A limitation of the current setup is that voice calls are strictly single-turn, which prevents the assistant from asking custom follow-up questions based on the customer's live responses.

6. CONCLUSION AND FUTURE WORK
